# 更新发布维护

## 三类版本

- 程序：`package.json` 和锁文件根版本一致，发布为 `v版本号`；协议1使用便携目录内稳定启动器加版本目录，后续包须保留 `server/desktop-app.js` 的启动握手。
- 题库：`public/catalog.json` 的 `libraryId=zju842`、`libraryRevision` 为递增整数。仅有程序变更时不要增加题库版本。既有题号不可随意删除或复用。
- 公共答案：`public/answers.json` 的 `revision` 递增，`requiresLibraryRevision` 指定最低题库版本。仅程序或题库变化时不要无故增加答案版本。

用户检查更新只读取公开仓库发布信息，不需要令牌。更新清单中的文件名和标签组成固定仓库下载地址，不能配置任意下载服务器。手动导入只接受数据包，不能导入任意程序 ZIP 执行。

## 发布答案

1. 在作者本地实例整理并定稿个人答案。
2. 使用“资料与备份 → 导出公共答案包”，明确勾选要公开的定稿，填写新的递增版本号。未勾选的私人答案、草稿和学习记录不导出。
3. 核对导出的图像和题号，确认素材可公开后执行 `npm run import:answers -- 路径/答案包.842answers`，仅将公共答案放入源码的 `public`。此命令不会发布。
4. 按正常发布流程生成新版清单和资源。不要把 `userdata`、私人备份或整个本地目录提交到仓库。

## 构建与发布

Windows、Mac Intel、Mac Apple芯片分别构建，运行自动化测试、`test:desktop`，并对便携包运行 `node scripts/test-update-desktop.js <程序目录>`。该测试复制到临时目录，模拟发布下载，实际执行升级、保留照片和记录、重启原快捷入口以及失败回退。

`publish-desktop.yml` 使用同一提交的成功 Desktop packages 产物，`npm run prepare:updates` 生成独立题库、答案包和 `zju842-updates.json`，先上传到草稿发布再公开为 latest。程序包不附带真实个人数据。仅更新题库或答案也可使用新的发布标签，但应保留各自未变的版本，客户端只下载需要的类别。

构建机器无法访问 Node.js 许可证地址时，可用 `npm run package:desktop -- --runtime-license <LICENSE路径>`；维护者必须确认该文件来自与当前运行环境相同版本的官方 Node.js 分发。本参数仅解决构建网络问题，不改变用户更新来源。

程序使用完整平台 ZIP 下载，不是二进制差分补丁。安装器只切换程序版本目录，不替换原始题库及公共答案目录；资料更新由对应入口独立处理。最初的稳定启动器和协议1保持兼容，若未来需要升级启动器协议，必须单独设计迁移，不能假定现有协议会执行不兼容的新启动器。
