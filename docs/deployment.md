# 部署说明

## 运行条件

需要一个支持 Node.js 24 和 HTTPS 的服务。前端与后端同源访问；存储使用持久磁盘上的 SQLite，或独立的 Turso 云数据库。GitHub 用于托管源码；静态页面托管不能单独承接登录、图片上传和纠错。

免费试运行可采用 [Render Free + Turso](render-turso.md)。本地测试不能替代实际云数据库与手机网络上的检查。

首版不绑定特定厂商。选择免费额度时必须核对磁盘是否持久、休眠规则、上传大小、流量额度和大陆实际可达性。带临时磁盘的免费服务会在重新部署时丢失答案，不能直接使用。没有经过实测的服务不视为已上线。

## 配置

```text
HOST=0.0.0.0
PORT=8843
DATA_DIR=/persistent/zju842
PUBLIC_ORIGIN=https://平台分配的实际网址
NODE_ENV=production
```

`PUBLIC_ORIGIN` 必须与浏览器网址的协议、主机和端口一致，不能带路径。反向代理终止 HTTPS，转发给 Node 服务；公网只开放 HTTPS。管理员 Cookie 在生产模式启用 Secure。

构建命令 `npm ci && npm run build`；启动命令 `npm start`。在服务使用的相同 `DATA_DIR` 下执行 `npm run admin:setup` 设置密码，再登录网页。切勿把密码写入源码、构建变量或截图。

后端默认不信任外部转发的 IP 头。置于代理后，登录和纠错限流可能按同一代理地址合并；选定实际平台后应按其可信代理地址配置，而不是直接信任任意 `X-Forwarded-For`。部署前验证多人提交互不误伤。代理上传限制应至少允许12MB文件加表单开销，上传超时需要覆盖手机网络。

## 容器运行

仓库提供 `Dockerfile` 与 `compose.yaml`。在有 Docker 的主机上运行：

```sh
docker compose up --build -d
docker compose exec web node scripts/setup-admin.js
```

默认只向本机的 `127.0.0.1:8843` 提供开发预览。公网部署前，在 `.env` 设置 `NODE_ENV=production` 和正确的 HTTPS `PUBLIC_ORIGIN`，配置反向代理后重新创建容器。容器以普通用户运行。

照片数据库保存在命名卷 `site-data`。`docker compose down` 不删除该卷；不要执行带 `--volumes` 的删除命令，除非已经备份并确定要清空站点数据。不要把卷内容复制进镜像或GitHub仓库。

## 保存与备份

管理员、会话、照片、草稿发布列表和纠错均存放在 `DATA_DIR/site.sqlite` 中。照片与发布状态使用同一数据库事务保存，避免文件写入成功但记录丢失。

备份时停止服务，将整个 `DATA_DIR` 复制到非公开备份位置后再启动。恢复时停止服务，用整份备份恢复到配置目录，再启动并检查答案。运行中不要仅复制主数据库而忽略 WAL 文件。备份包含私人草稿及账号验证信息，不上传公开仓库。浏览器学习记录由各访客自行导出。

## 首次公开前

1. 确认 GitHub 账号、仓库名、代码许可证以及素材条款，只把 `web` 作为仓库根目录。
2. 检查待提交内容不含 `.env`、`data`、`.test-artifacts`、原 PDF、整页扫描、历史答案草稿或日志。
3. 运行构建、自动测试和依赖检查；设置生产管理员密码。
4. 在实际公开网址测试匿名阅读、分享、纠错，确认非管理员不可编辑或读取草稿。
5. 用红米手机拍照、相册选图、旋转、替换、发布及撤下；另一个未登录浏览器核对公开效果。
6. 在大陆普通网络分别检查首页、题图、答案和上传。关闭维护者电脑后再检查公开网址；重启或重新部署后检查答案仍然存在。

开发仓库提供持续集成构建和测试，不自动创建公网服务或启用收费资源。
