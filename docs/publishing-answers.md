# 向所有使用者发布公共答案

你的电脑是内容维护端，但程序里没有自动向其他电脑同步的“母版本”。**导入照片、标为定稿、导出答案包、正式发布，是四件不同的事。**

| 操作                 | 结果                         | 其他用户会收到吗                   |
| -------------------- | ---------------------------- | ---------------------------------- |
| 导入答案截图         | 存入本机私人草稿             | 不会                               |
| 标记为定稿           | 成为本机“我的答案”           | 不会                               |
| 导出公共答案包       | 生成你明确选中的可公开资料包 | 不会自动收到                       |
| 发布答案包及更新清单 | 官方更新源提供新版本         | 用户检查“公共答案更新”后可下载安装 |

## 你需要做的部分

1. 在对应题目中打开“查看答案 → 编辑我的答案”，导入照片并调整顺序、方向。
2. 校对后“标记为定稿”。仍然只保存在你的电脑，不会自动上传。
3. 返回目录，打开“资料与备份 → 导出公共答案包”。
4. **只勾选愿意公开的定稿**，填写更大的答案版本号和本次说明。当前公开答案是r0，第一批可用r1。
5. 保存导出的 `.842answers`，交给维护者完成发布；不需要交出整个userdata或私人备份。

导出包包含当前已有的公共答案，再用选中的定稿新增或替换对应题目。它是完整公共答案版本，不是“只传本次改动”的补丁。没有勾选的私人答案和草稿不会公开。

如果要发布第二批，维护用副本应先拥有上一批公共答案，再继续导出，避免用过时的公共索引漏掉旧内容。撤回某一道公共答案也需要维护完整索引并提高版本号，不能只上传一个空文件覆盖。

## 发布端需要做的部分

1. 解包检查题号、图像、版本和可公开范围。在两个独立资料目录中验证：作者导出、普通用户导入；公共答案变化不能覆盖消费者的“我的答案”。
2. 执行 `npm run import:answers -- <已核对的文件.842answers>`，把公开内容准备到源码的 `public/answers.json` 和 `public/answers/`。这一步仍不等于发布。
3. 生成答案包与 `zju842-updates.json`。答案修订号递增，声明最低题库和程序版本；未修改的程序版本与题库版本保持不变。
4. 将答案包和清单上传到受信任仓库的新Release。先在草稿中补齐资源，再设为最新发布；程序、题库清单项可继续引用原有Release中的文件。
5. 用普通用户的隔离副本检查：只出现公共答案更新；下载安装后能看见新图，原有收藏、题单、轮次与私人答案保留。

只更新答案不必让所有人重新下载完整程序。现有桌面自动发布工作流针对完整程序版本；纯答案发布需要单独组装完整更新清单，并保留未变的程序／题库引用，不能直接把答案包丢到仓库文件区，也不能把只有答案的残缺清单替换正式清单。

正式更新源为本项目GitHub Release。普通用户本地也能整理或导出自己的资料，但没有仓库发布权限就不会改变所有人的公共答案。

## 交给维护者时说明

- 本次哪些题的答案可以公开，有无替换或撤回。
- 答案包文件及期望的版本说明。
- 是否依赖本次新增题目；如依赖，先确定对应题库版本。

其余打包、验证和发布可以由维护工具或AI协助完成；选择公开哪些个人答案仍由你决定。
