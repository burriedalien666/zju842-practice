# 题面结构化：分批制作与迁移

更新：2026-09-26。全部250组／469条已制作、用户已核验，现已完成接入并纳入v0.5.9正式发布（题库r4）。当前结果见[本地接入记录](structured-integration.md)；下文保留分批制作与核对办法，适用于后续新增和返修，不表示还有未制作批次。

本文件是[后续更新计划](roadmap.md)的实施说明。实际条目与结论分别记录在本地的“结构化进度.md”和“准确性复核记录.md”，疑点单列“疑点题记录.md”，不复制多套清单。本机查看入口：[结构化资料索引](../../结构化资料索引.md)。

## 分批方式

- 2026-09-24根据用户对错漏与长上下文的反馈，当前改为每次2—3个原题组，复杂电路1—2组。此前6—8组为历史执行安排；内部批号可拆成多个工作段，但共享题干/小问不拆开计数。
- 按来源清晰度与图形复杂度搭配批次，所有组都完成第二遍来源核对和显示检查。有疑点单独记录，不为凑通过数猜改题意或省略复核。
- 共享题干／图形连同相关小问作为一个原题组制作，最终仍逐个绑定原题ID。不能把共用一张图的小问当成多次独立完成。
- 制作一遍，重新对原图复核一遍，再看实际渲染；复核时不只对照自己生成的数据。
- 方程以完整单行为默认；实际可用宽度不足时才在等号、加号等合适位置使用等价换行，不为兼容手机让桌面也固定分行。公式不得出现内部竖向滚动条或截断，需检查比较模式、字号变化及窗口缩放。
- 优先复核已制作待校对稿，再增加新题；来源疑点单独记录，不让未解决的一题阻塞其他清楚题目。

首批9组对应16条原题记录的展示内容，当时只有9个样题入口；后续累计数见进度表。“展示包含”与“正式题库已接入”分开统计。

## 选择“整批迁移”，不逐题上线，也不等全库

采用“隔离制作 → 逐组内容复核 → 批次接入检查 → 小批迁移”的方式。

内容样题站保留为原图对照与制作记录；正式程序现已接入独立的结构化题面格式和更新机制。原题ID及个人资料保持，结构化与旧截图题库仍兼容；迁移通过程序渲染、独立题库包和原安装流程完成。

首次接入要验证以下真实使用路径：

- 同一题在章节、整卷和历史回看中内容一致。
- 共享题干的所有小问都有正确原题ID，答案和视频链接仍指向原题。
- 题库更新与最低程序依赖正确，旧客户端得到明确提示。
- 收藏、自评、题单、计时、轮次与私人照片经过更新仍保留。
- 发现内容错误时可以回退该题显示为原图，不恢复或覆盖用户后续学习记录。

之后每次迁移已经核验的完整题组。2026-09-26按用户确认，已有待核来源稿也统一启用结构化显示；疑点仅保留在维护复核文档，做题页只提供原图对照，不擅自校订，也不自动退回截图。未来未制作的新题仍可使用原图。

本机日常版已通过原启动器的更新链路迁移；跨平台公开发布按构建、启动及升级回退检查执行。

## 三份记录各管什么

**结构化进度.md**：题号、来源、题组与小问映射、实现文件、制作／复核／迁移状态、下一批范围。记录“已经做了什么”，不重复计算改稿次数。

**准确性复核记录.md**：核过的文字、公式边界、图表／引脚／线网、实际显示和修正。每组有明确结论，不能只写“模型觉得没问题”；遇到来源歧义，链接到疑点记录。

**疑点题记录.md**：按原题ID集中列出有疑点的题、具体问题、来源位置、当前处理及需要的核实资料。既记录未制作／未通过的题，也记录已忠实转录但数学意图未确认的题。疑点解决后保留依据和重核结论，不直接删掉。

状态区分为：已制作待复核、内容复核通过、需修正、来源待核、本地已接入、已公开迁移。当前250组已接入；来源疑点与显示接入分别记录。

## 精确度检查

1. 文字与公式逐项对应原卷，尤其否定词、正负号、上下标、取反范围、分段边界、积分上下限和单位。
2. 波形记录坐标、幅值、周期、端点和图例；状态图逐条核起点、输入、终点、输出；表格逐格核对。
3. 电路核引脚、低有效小圆点、时钟边沿、导线端点、跨线和连接点。没有数值或图像模糊时不猜。
4. 对某些表达式可做真值表、边界样值等辅助检查，但数学自洽不等于抄对原题。
5. 同一助手分开两遍检查，不称为独立人审；显示测试通过也不称为专业内容已完全准确。

只使用Git、原题ID、已有数据校验、常规测试及这两份记录，不额外添加文件哈希、冻结清单或复杂审批层。首次正式接入／发布才检查完整的数据与升级兼容性。

## 模型与工作强度

本阶段继续使用用户当前选择的GPT-6 Astra“极高”，沿用当前任务，不新建对话。

这是针对精度优先、混合公式与图形核验的工程选择，不是“每一道普通文字题都必须极高”的结论。简单排版和机械录入可以用较低强度，但复杂公式、图形连接和最终内容复核当前不降档，也不需要升到更高档位。

[官方模型说明](https://developers.openai.com/api/docs/models/gpt-6-astra)将Astra定位于复杂端到端工作，支持xhigh等推理强度。没有官方依据能证明某档位对本题库必然零误差；清晰来源、分开复核和小批检查比仅提高档位更重要。若以后考虑降档，先在少量已核题上比较错漏与复核成本，再决定，不直接拿未核电路试错。

## 内容底线

保持原题号、共享关系和用户学习资料，原图保留作为对照。正式渲染使用本地KaTeX与声明式SVG，继续区分显示验收、来源确认和公开发布。

不增加解题答案，不将原卷歧义擅自修成另一道题，不把样题验证记录写入用户的做题记录。通用框架等其他方向仍在计划末尾，不在这轮展开。
