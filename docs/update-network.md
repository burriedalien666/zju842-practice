# 更新网络与诊断

v0.5.4 的程序、题库和公共答案共用更新下载器。更新中心仍只在用户确认后安装；检查更新不会上传答案或学习记录。

## 默认连接方式

每次检查或下载都会读取当前资料目录中的配置。未配置时使用 `auto`：

1. 有 HTTP/HTTPS 环境代理时优先使用它。
2. 没有环境代理时，读取 Windows 当前用户的静态系统代理或 macOS 系统代理。
3. 没有配置代理时直接连接 GitHub。

这只影响更新下载器，不改变系统代理、浏览器或本机题库连接。原稳定启动器升级后也由新版程序加载这一下载器，不要求替换原启动文件。

PAC/WPAD、仅 SOCKS 的代理、NTLM/Kerberos 自动登录不支持。遇到这些配置会说明原因，不擅自改为直连。不要关闭 TLS 证书校验或防火墙来解决下载失败。需要企业证书时，请由网络管理员提供可信配置。

## 检查失败怎么办

- **本地服务断开**：重新运行原目录的“启动题库”，在同一浏览器打开生成的新页面。有未保存改动先导出，不要刷新或关闭旧页。
- **启动会话失效**：使用启动器生成的链接重新建立会话，仅输入旧网址不一定有效。
- **GitHub接口、清单或CDN连接失败**：确认网络与代理可用，点击“检查更新”重试。已有题目仍可使用。
- **磁盘不足或安装失败**：先按错误提示处理，不反复安装；旧版和个人资料应保留。若提示临时文件清理未完成，不要盲删资料目录。

自动检查最多复用6小时缓存，“检查更新”会重新联网。可重试的网络故障最多尝试3次；整包中断从头下载，不做续传。清单检查总时限20秒，整包下载总时限30分钟，连接空闲时限30秒。界面最多等待32分钟确认更新结果。磁盘、认证、证书或内容校验错误不会靠反复安装解决。

## 导出诊断

更新中心的“导出脱敏更新诊断”可在本机服务正常时使用，不依赖GitHub连通。包含运行时、平台、代理来源和最近更新错误阶段，不包含代理地址/密码、启动令牌、个人照片或学习记录。更新事件只保留最近50条，重启后内存事件消失，建议失败后及时导出。

源码维护者可运行：

```sh
node scripts/diagnose-updates.js --data-dir "<当前资料目录>"
node scripts/diagnose-updates.js --data-dir "<当前资料目录>" --check
```

默认只读本地配置；`--check` 会读取GitHub清单，不安装更新。资料目录可在“资料与备份”中查看。

## 特殊网络的显式配置

普通用户通常不需要编辑。需要明确指定连接路径时，在当前资料目录放置 `update-network.json`，下一次检查生效：

```json
{"mode":"system"}
```

支持 `auto`、`system`、`environment`、`proxy`、`direct`。`direct` 仅用于用户确认允许直连的网络；不应绕过单位网络要求。

显式 HTTP/HTTPS 代理示例：

```json
{"mode":"proxy","proxyUrl":"http://127.0.0.1:7890","noProxy":"localhost,127.0.0.1"}
```

7890只是示例，不要照抄。只使用你或网络管理员提供的代理。配置可包含Basic认证，含凭据时属于本机秘密，不要发送到聊天、提交源码或放入发布包。配置非法或读取系统设置失败时，不会悄悄切换直连。

更新下载使用固定官方GitHub域名，不要求GitHub令牌，不内置第三方镜像。网络适配不保证所有地区或受管理网络都能访问发布资源；必要时使用浏览器取得完整包，按[旧版恢复与迁移](old-version-recovery.md)处理。
