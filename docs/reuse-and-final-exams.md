# 通用框架与期末题：当前兼容范围

这份说明用于评估，不表示开始新增功能或框架重构。

## 能否做成通用框架

可以，但目前仍是842专用应用，并不是拿任意PDF就能一键生成网站的通用产品。

已经能复用的部分包括单题界面、题单、自评、个人照片、轮次记录、本地存储、便携启动器和更新安装逻辑。需要解耦的部分包括：

- 科目和章节：当前校验与界面以signals／digital两科为主，有842专用分类。
- 项目身份：题库ID、程序名、文件名、端口、资源命名及数据目录要独立配置，避免两套题库混用记录。
- 更新源：当前固定到本项目的GitHub仓库；派生题库不能继续从842官方源接收别人的资料。
- 试卷结构：来源、课程、年份、学期、卷别与大题／小问需要明确映射，不能只靠年份分组。
- 内容制作：PDF拆题、OCR、公式转录、图形重绘和答案关联属于资料生产，不会因为有网页模板就自动可靠完成。

| 目标                                                 | 工作量判断                                                                       |
| ---------------------------------------------------- | -------------------------------------------------------------------------------- |
| 同两科、换题目和标题，继续使用当前交互               | 较小的适配工作，主要在资料整理与验证。                                           |
| 任意学校／学科、独立题库和更新源，可由AI按模板装配   | 中等重构：抽出配置与内容接口，增加另一套真实样本验证隔离。                       |
| 任意扫描试卷输入后自动得到高质量文字、公式与电路题库 | 大工程：需要识别、纠错、共享题干、图形重建和逐题核对，不能承诺零校对的一键产物。 |

建议未来先交付“通用底座＋内容格式说明＋AI整理指引＋可运行样例”，让AI按固定输入格式整理试卷。题面结构化时可以保持数据与渲染分离，但不因此提前开展全面通用化。

## 追加期末题能否兼容

当前数据支持sourceKind为final，能在题源筛选中与考研题区分；复用信号与系统或数字电路的题型，可进入章节与题型练习。未映射的新题型有待归类入口，正式发布前仍应完成分类核对。

**整卷范围不同：**“历年真题”当前只收录entrance考研试卷。期末题不会自动混进考研整卷或考研热力图。若希望按课程、学期、A/B卷分别做完整期末卷，需要另行扩展试卷分组和入口。

本次维护已发现并修复作者导入器会丢失现有题库根元数据的问题；修复在源码维护脚本中，不要求现有用户重装客户端。新增回归使用真实r2题库的隔离副本，检查版本、课程目录、既有题号和题图不变。

## 提供期末卷时需要什么

- 原PDF或清晰扫描，注明课程、年份、学期和卷别。
- 是否附答案，哪些内容可以公开。
- 希望先逐题归入章节，还是需要单独期末整卷入口。

在现有两科按题追加时，程序改动通常较少，主要工作量是拆题、分类、图像与题号校对。新增科目、特殊题型或期末整卷模式需要额外适配。没有具体试卷前不承诺固定工期，也不能保证未见过的版式没有新问题。

发布前先用一小份期末卷验证重复题号、同年多卷、跨页题、多图小问、答案关联、原有学习记录和更新依赖，再决定整批导入。所有检查使用副本，不拿日常资料试错。
